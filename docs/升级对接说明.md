## 二、服务器端部署步骤

```bash
# 1. 拉最新代码
cd <deepseek-fish 仓库目录>
git pull origin main

# 2. 部署热搜 MCP（新）
mkdir -p /opt/hot-search-mcp
cp mcp/hot-search-mcp.js /opt/hot-search-mcp/
cp mcp/hot-search.mjs /opt/hot-search-mcp/

# 3. 部署新 skill 到 DSH 可发现目录
#    把 .agents/skills/ 下的 9 个 skill 复制到 ~/.agents/skills/（或 DSH 的 skill 目录）

# 4. 更新 cordis.patch.yml（挂载 hot-search MCP）
#    把 server/cordis.patch.yml 里的 mcp-hot-search 段合并进 /root/.dsh/profiles/web/cordis.patch.yml

# 5. 重新打补丁（记忆 RAG 有更新）
#    见 patches/README.md，在干净的 qq-bridge v0.1.0 上应用 4 个补丁，
#    或增量应用更新后的 0004-memory-rag.patch

# 6. 重启服务
systemctl restart dsh-web qq-bridge
```

## 三、config.json 需要关注的字段

```jsonc
"longMemory": {
  "isolation": false,          // 已改回 false，恢复跨会话时间线（原来是 true）
  "embedding": {
    "enabled": false,           // 是否开语义检索（见下方电脑端说明）
    "url": "http://127.0.0.1:8897",   // 电脑端 embedding 服务的反向隧道地址
    "modelPath": "/opt/models/...",   // 或服务器本地模型路径
    "minSemantic": 0.4          // 实测校准值（bge-small-zh）
  }
}
```

## 四、电脑端（可选：开语义检索才需要）

embedding 模型放电脑端（2核2G 服务器不背模型）：

1. 电脑上 `npm i @huggingface/transformers`
2. 下载 `Xenova/bge-small-zh-v1.5` ONNX 模型
3. 改 `desktop/run-embed.bat` 里的 `EMBED_MODEL_PATH` 和 `{{BRIDGE_DIR}}`
4. 守护进程已加 8897 隧道和自动重启（`phone-mcp-daemon.ps1`）

## 五、注意事项（重要）

1. **先备份**：`config.json`、`state/` 目录更新前先备份。
2. **补丁冲突**：`0004-memory-rag.patch` 有更新，旧实例不要直接覆盖，建议在独立目录用干净 v0.1.0 重建验证后切换（见 `docs/记忆RAG升级.md`）。
3. **白名单**：`qq-tool-restrict.mjs` 已加 `mcp__hot-search__` 前缀，部署时记得同步这个文件，否则热搜工具会被拒绝。
4. **isolation 变化**：`longMemory.isolation` 从 true 改成 false，恢复跨会话时间线（群里说过的话私聊接得上），代价是放弃跨群隐私隔离。确认这是你要的。
