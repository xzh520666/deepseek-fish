# 升级对接说明（本次功能更新）

> 面向部署者。本次更新涉及记忆检索、遗忘模型、情绪策略、skill 体系、热搜 MCP、embedding 服务等。请按下面步骤更新，**更新前先备份 config 和 state**。

## 一、这次改了什么

| 模块 | 内容 | 影响 |
|---|---|---|
| 记忆检索 | `minSemantic` 可配置（默认 0.4）、embedding 持久化复用、会话隔离、去重版本链 | 改了 `patch/0004` + 新增 `mcp/memory-store.mjs`、`mcp/memory-retriever.mjs` |
| 情绪策略 | 5 种回应策略 + 减少误判（反讽/第三方主语/歧义） | 改了 `persona/emotion-policy.mjs` |
| skill 体系 | 9 个按需 skill（game-chat/sticker/qzone/slang/img + proactive-memory/anti-flip/vibe-sense/humanizer-cn） | 新增 `.agents/skills/` 目录 |
| 游戏梗知识库 | 6 游戏（火影/原神/崩铁/我的世界/LOL/CS2） | `.agents/skills/game-chat/references/` |
| 热搜 MCP | 微博/知乎双源 `get_hot_search` | 新增 `mcp/hot-search.mjs` + `hot-search-mcp.js` |

## 二、服务器端部署步骤

```bash
# 1. 拉最新代码
cd <deepseek-fish 仓库目录>
git pull origin main

# 2. 部署热搜 MCP（新）
mkdir -p /opt/hot-search-mcp
cp mcp/hot-search-mcp.js /opt/hot-search-mcp/
cp mcp/hot-search.mjs /opt/hot-search-mcp/

# 2.5 部署记忆模块（遗忘模型 + 时间解析，和 memory-store 一起放 bridge 的 src）
cp mcp/forgetting.mjs mcp/due-parse.mjs /opt/qq-bridge/src/

# 2.6 部署后台管理服务（web/server.mjs，独立服务，读写 state 文件）
# 同源托管 web/ 前端 + 提供记忆/mood 管理 API，不依赖 bridge 的 3100 API
cd <deepseek-fish 仓库目录>
# 默认 STATE_DIR=/opt/qq-bridge/state，端口 8081；有需要可加 systemd 服务
STATE_DIR=/opt/qq-bridge/state node web/server.mjs --port 8081
# 浏览器打开 http://<服务器IP>:8081 即可用后台（记忆中心 + mood 仪表盘）

# 3. 部署新 skill 到 DSH 可发现目录
#    把 .agents/skills/ 下的 9 个 skill 复制到 ~/.agents/skills/（或 DSH 的 skill 目录）

# 4. 更新 cordis.patch.yml（挂载 hot-search MCP）
#    把 server/cordis.patch.yml 里的 mcp-hot-search 段合并进 /root/.dsh/profiles/web/cordis.patch.yml

# 5. 重新打补丁（记忆 RAG 有更新）
#    见 patches/README.md，在干净的 qq-bridge v0.1.0 上应用 4 个补丁，
#    或增量应用更新后的 0004-memory-rag.patch

# 6. 重启服务
systemctl restart dsh-web qq-bridge
```

## 三、config.json 需要关注的字段

```jsonc
"longMemory": {
  "isolation": false,          // 已改回 false，恢复跨会话时间线（原来是 true）
  "embedding": {
    "enabled": false,           // 是否开语义检索（见下方电脑端说明）
    "url": "http://127.0.0.1:8897",   // 电脑端 embedding 服务的反向隧道地址
    "modelPath": "/opt/models/...",   // 或服务器本地模型路径
    "minSemantic": 0.4          // 实测校准值（bge-small-zh）
  }
}
```

## 四、电脑端（可选：开语义检索才需要）

embedding 模型放电脑端（2核2G 服务器不背模型）：

1. 电脑上 `npm i @huggingface/transformers`
2. 下载 `Xenova/bge-small-zh-v1.5` ONNX 模型
3. 改 `desktop/run-embed.bat` 里的 `EMBED_MODEL_PATH` 和 `{{BRIDGE_DIR}}`
4. 守护进程已加 8897 隧道和自动重启（`phone-mcp-daemon.ps1`）

## 五、注意事项（重要）

1. **先备份**：`config.json`、`state/` 目录更新前先备份。
2. **补丁冲突**：`0004-memory-rag.patch` 有更新，旧实例不要直接覆盖，建议在独立目录用干净 v0.1.0 重建验证后切换（见 `docs/记忆RAG升级.md`）。
3. **白名单**：`qq-tool-restrict.mjs` 已加 `mcp__hot-search__` 前缀，部署时记得同步这个文件，否则热搜工具会被拒绝。
4. **isolation 变化**：`longMemory.isolation` 从 true 改成 false，恢复跨会话时间线（群里说过的话私聊接得上），代价是放弃跨群隐私隔离。确认这是你要的。

## 六、验收清单（部署后逐项验证，照着打勾）

### A. 记忆检索
- [ ] 语义检索：开 embedding 后，问"LOL"能召回"英雄联盟"相关记忆（关键词不重叠、靠语义）
- [ ] 会话隔离：A 群的记忆不会在 B 群被召回
- [ ] 若语义检索频繁漏召回，检查 `minSemantic` 是否为 0.4

### B. 遗忘模型
- [ ] 后台记忆列表能看到遗忘状态（硬事实=绿「硬事实」，偏好=黄「快忘」）
- [ ] 作废后不再被检索，恢复后重新检索（后台「作废/恢复」按钮）
- [ ] 标记「召回错」后，该记忆排序降权（badHit 反自强化）

### C. 情绪 / mood
- [ ] 被骂/被夸时回应策略不同（安慰/倾听/解决问题，emotion-policy 的 5 策略）
- [ ] mood（若已接线）：AI 心情随对话漂移，后台 mood 仪表盘能看、能调

### D. 热搜 MCP
- [ ] `node mcp/hot-search-mcp.js --selftest` 能返回微博/知乎热搜
- [ ] 群里冷场时，AI 会主动用热搜抛话题

### E. skill 体系
- [ ] 聊到具体游戏（如"云顶这版本什么阵容"），AI 用 game-chat 的梗知识接
- [ ] 人设瘦身后，AI 说话语气没明显变差（去 AI 味底线还在）

### F. 后台管理
- [ ] 管理服务起来：`STATE_DIR=/opt/qq-bridge/state node web/server.mjs --port 8081`
- [ ] 浏览器打开 `http://<服务器IP>:8081`，能看记忆列表 + 遗忘打分
- [ ] 「作废/恢复/召回错」三个按钮能正常改记忆状态
- [ ] mood 仪表盘能显示当前状态、点「设为开心/平静/疲惫」能改

### G. 回归检查
- [ ] 单元测试通过：`node --test tests/*.test.mjs`（61 个，0 失败）
- [ ] 核心聊天没回归：正常收发消息、被动模式、记忆注入都还正常

> 任何一项 ✗，记录现象 + 相关日志（`journalctl -u qq-bridge -n 50`）反馈，别自己瞎猜改配置。
